The Orange Case

A cloud-native party game in a hard case. Same game, same telemetry, same chaos challenges. Only the observability backend changes.

See the challenges JoustMania on GitHub

What is it?

Two meanings, one case: a physical orange hard case you can carry to a booth, and a reproducible test case for observability backends.

The game

JoustMania

Up to 25 players with motion controllers. Move too fast and you're out. Every swing, death and win is a span.

The telemetry

OpenTelemetry, all signals

Traces, metrics and logs from every service, with a published, versioned attribute schema.

The control plane

OpenFeature + flagd

Every challenge is a live flag flip, and the flip shows up as a span event on your own trace timeline.

Architecture

Everything runs inside the case. The collector exports over OTLP/HTTP on port 443, one profile per backend, so venue firewalls aren't a problem.

The challenges

Three core challenges run live at every participating booth. Four extended ones run any time through the stowaway CLI.

Core · live

Swing-to-screen latency

A controller gets knocked out. How long until that death event appears in your UI? The clock is running.

Core · live

Million-span match

One match, one trace, about a million spans. Can your backend ingest it, sample it and render the waterfall?

Core · live

Find the cheater

A flag quietly makes one controller cheat. You have two minutes and your own tool to find out which one.

Extended

Cardinality bomb

High-cardinality per-swing and per-player metric attributes.

Extended

Hostile Wi-Fi

The uplink drops mid-match. Does everything backfill correctly when it comes back?

Extended

Clock-skewed controllers

Drifting timestamps: does your backend flag the skew or silently reorder spans?

Extended

All-signals correlation

Traces, metrics, logs, flag events and profiles from a single match.

Stowaway: test before you meet the case

Stowaway generates the same telemetry as the real case, so you can tune your ingest pipeline against your own endpoint well before the event. It's in development, so commands may still change.

# run a core challenge against your own OTLP/HTTP endpoint
docker run --rm ghcr.io/orange-case/stowaway \
  run --challenge million-spans \
      --endpoint https://otlp.example.com \
      --header "Authorization=Bearer $TOKEN"

Every synthetic span and metric carries orangecase.synthetic=true. Challenges: swing-latency, million-spans, find-cheater, cardinality-bomb, hostile-wifi, clock-skew.

For vendors

This is a benchmark, not an ambush. The schema, the challenge definitions and stowaway are published at least six weeks before the event, so you can test against your own endpoint in advance.

  1. Opt in with your booth number and a nominated Solutions Engineer for the live slot.
  2. Provide an OTLP/HTTP endpoint (TLS on 443) and an API key header. We set up one isolated exporter profile per vendor.
  3. Get the attribute schema early and pre-build your dashboards and queries.
  4. Dry-run with stowaway against your staging or production endpoint.
